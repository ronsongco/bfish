## Key Decisions
- Evaluate offline translation models in a separate workstream from WhisperKit model evaluation because transcription and translation errors must be attributable to the correct stage.
- Use identical source inputs and fixed degraded transcripts across LLM candidates; do not rerun WhisperKit for every translation-model comparison.
- Publish per-language scores so strong performance in one language cannot hide weakness in another.
- Publish both quality-first and live-use rankings rather than relying only on one aggregate score.
- Mark models ineligible when they frequently violate mandatory behavior even if their aggregate score is high.
- Keep model names, parameter sizes, and quantizations in benchmark data/configuration rather than application code.

## Important Context
- `README.md` is authoritative for the benchmark design and full architecture.
- Priority languages are Japanese, Korean, Mandarin, and Brazilian Portuguese; secondary languages are Tagalog, Spanish, and Italian.
- The proposed speaker model uses stable anonymous labels by default. Diarization does not identify a real person's name or role unless the user supplies an alias.
- Overlapping speech, short interjections, similar voices, music, and compression can reduce speaker attribution accuracy.
- Ollama must never infer speaker identity or merge text across speaker turns.
- Open-source SpeakerKit is suitable for file/post-processing workflows; accurate real-time attribution should remain a later or experimental scope unless evaluation proves otherwise.

## Tool & Dependency Requirements
- Current planned runtime requirements remain documented in `README.md` and `.session/2026-08-18_16-27.md`.

- Benchmark execution requires Ollama plus enough local disk and unified memory for each candidate model and concurrent-load tests.
