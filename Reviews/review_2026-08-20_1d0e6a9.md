## 1. New defects

### 1.1 `contextTurns` grows without bound for the life of a session

`Sources/BFishCore/Pipeline/TranslationPipeline.swift:43,120,133,151,165`

`contextTurns` is appended in four places and cleared only at session start (line 76) and
`endSession` (line 193). It is never trimmed.

`boundedContext` reads only `turns.suffix(turnLimit)` — at most 4 turns live, 8 offline — so the
array's entire history is retained and never read. For a three-hour live session at one utterance
every few seconds, that is thousands of `TranscriptTurn` values, each holding source text, English
text, UUIDs, and a `CaptureTimeline`, held until the session ends.

This directly contradicts `README.md:225`: "use an explicit recovery policy instead of silently
growing memory without bound."

Severity is highest for the live profile, which is precisely the long-running one. Fix is one line —
trim to `contextTurnLimit` (or a small multiple) on append.

### 1.2 The default `CaptureTimeline` fabricates a unique timeline per segment

`Sources/BFishCore/Domain/TranscriptModels.swift:117`

```swift
timeline: CaptureTimeline = CaptureTimeline(),
```

`CaptureTimeline()` mints a fresh `UUID` on every call, so every default-constructed
`RecognizedSegment` belongs to a *different* capture timeline.

Timeline identity exists to group segments from one capture and to make a discontinuity visible
after a device reconnect (`README.md:228`). A default that silently invents a distinct identity per
segment produces correlation data that looks structured and means nothing — worse than an absent
field, because a consumer cannot tell the difference between "these came from different timelines"
and "nobody set this."

All 12 tests currently exercise this default, so the propagation added in this commit is untested in
its intended grouping role.

Recommendation: make `timeline` a required parameter so the adapter must supply the session's
timeline, or hold it on the pipeline session and stamp it centrally.

### 1.3 Suppressed non-speech turns consume the context budget, and can zero it out

`Sources/BFishCore/Pipeline/TranslationPipeline.swift:118-129`

A segment exceeding `maximumNoSpeechProbability` is turned into a source-only turn and **appended to
`contextTurns`** (line 120), so a segment the pipeline just judged to be probably-not-speech becomes
context for the next translation.

This compounds with the (correct) new `break` rule in `boundedContext`. Whisper's silence
hallucinations are often long — a full "thanks for watching, don't forget to subscribe" sentence. If
such a segment is suppressed and appended, then on the **very next** segment its `characterCost` can
exceed `characterLimit` on its own, hitting the `cost > characterLimit` break at line 207 and
returning an **empty** context.

Net effect: one suppressed hallucination silently strips all conversational context from the
following translation, which is the exact quality regression context exists to prevent. Nothing in
the diagnostics would show why.

Fix: do not append suppressed turns to `contextTurns`. They are still yielded as transcript events,
so nothing is hidden from the user.

### 1.4 Two classes of non-speech, opposite observability

- `hasMeaningfulContent` returns false → `handle` returns `[]` (line 116). No transcript, **no
  diagnostic**, no counter. The segment vanishes without trace.
- High `noSpeechProbability` → transcript yielded **plus** a `translation_suppressed` diagnostic.

Two non-speech paths with opposite visibility, and only one is measurable. The scoreboard allocates
10 points to hallucination control (`README.md:457`); scoring it requires counts of what was
filtered, not just what was suppressed. A silent filter is also the hardest kind of bug to notice
when tuning gates against golden fixtures.

Recommendation: emit a `segment_filtered` diagnostic with a reason on the first path.

### 1.5 The bracket filter misses CJK full-width brackets — the primary language set

`Sources/BFishCore/Pipeline/TranslationPipeline.swift:225-228`

```swift
if let first = trimmed.first, let last = trimmed.last,
   ["[", "("].contains(first), ["]", ")"].contains(last) {
```

This matches ASCII brackets only. Japanese and Chinese non-speech markers conventionally use
full-width and CJK bracket forms, none of which match:

| form | example | matched |
|---|---|---|
| `（ ）` U+FF08/U+FF09 | `（笑）` | no |
| `［ ］` U+FF3B/U+FF3D | `［音楽］` | no |
| `【 】` U+3010/U+3011 | `【拍手】` | no |
| `〔 〕` U+3014/U+3015 | `〔音楽〕` | no |

Japanese, Korean, and Mandarin are three of the four primary languages (`README.md:74-77`), so the
filter misses the bracket convention most likely to appear in the project's main corpus. Widening
the character set is a one-line change.

### 1.6 Strictly sequential translation plus a 15-second live timeout blocks the head of the line

`TranslationPipeline.swift:83-88` processes segments in a serial `for` loop, awaiting `handle` — and
therefore the full translation — before touching the next segment. `PipelineProfile.live` sets
`translationTimeout` to 15 seconds (line 25).

Against a stated 2–4 second latency target (`README.md:101`), a single stalled translation produces
**fifteen seconds of no output**, during which live audio keeps arriving with nowhere to go. Steady
state is worse than the spike: if translation averages 3s and utterances arrive every 2s, the
pipeline falls behind by 1s per utterance indefinitely. There is no lag detection, no queue-depth
diagnostic, and no recovery policy in the pipeline — all three are required by `README.md:223-225`.

The `AudioBufferingPolicy` in `PipelineProfile` bounds the *audio* side, but nothing bounds pending
translations, which is where the backlog actually forms.

Recommendations, roughly in order of value: shorten the live timeout to something inside the latency
budget (~5s); add a pending-translation depth bound with a diagnostic when it is exceeded; and
consider bounded-concurrency translation with ordered emission so one slow utterance does not stall
the ones behind it.

## 2. Smaller items

### 2.1 `LanguageTag` is now dead code

`grep` across `Sources/` and `Tests/` returns zero references to `LanguageTag` outside its own file.

It was retained to carry locale-specific values such as `pt-BR`, but `TranscriptTurn.language` is now
`WhisperLanguage`, so `TerminalTranscriptFormatter` can only ever print `pt`. The `pt-BR` capability
described at `README.md:270` has no path to the output.

Either wire a session locale tag onto the turn or the formatter, or delete the type. Leaving an
unused public type that appears to solve a documented requirement is the worst of the three.

### 2.2 The batch path defaults to live tuning

`TranslationPipeline.init` defaults to `profile: .live` (line 48), and `process(...)` is documented
as the batch convenience for files. So the milestone-2 audio-file workflow will silently run with
live defaults — 4 context turns, 2,000 characters, 15s timeout — rather than the offline profile's
8 / 6,000 / 60s.

Nothing selects a profile from the CLI yet, so this will be the de facto configuration for the first
real transcription work unless a caller overrides it. Worth making the profile explicit at the call
site before milestone 2 produces numbers that get treated as the offline baseline.

### 2.3 Session lock has no recovery path or diagnostic

`activeSessionID` is set inside `events(...)` (line 75), before any consumer iterates. A caller that
creates the stream and retains it without consuming holds the instance locked indefinitely;
`sessionAlreadyRunning` carries no session identifier, start time, or hint. It self-heals if the
stream deallocates, but there is no diagnostic event for the rejected attempt.

### 2.4 Late translation can append to a cleared context

`handle` checks `activeSessionID == sessionID` on entry (line 116) but not after the `await` at line
145. On cancellation, a translation that completes after `endSession` has cleared `contextTurns`
still appends to it. It self-corrects because `events(...)` resets the array, but the window leaves
stale state on the actor between sessions. A post-await guard closes it.

### 2.5 Unquoted variable in the packaging script

`Scripts/package-local.sh:17` — `version="$($binary_path version | ...)"`. `$binary_path` is
unquoted and will break on a path containing spaces. Harmless at the current path; trivial to fix.

### 2.6 Two version surfaces

`CommandConfiguration(version: BFishCore.version)` provides `bfish --version`, and `VersionCommand`
provides `bfish version`. Both read the same constant today, so they cannot drift — noting only that
`package-local.sh` depends on the `version` subcommand's exact output shape (`awk '{print $2}'`),
which makes that string format load-bearing for packaging.

## 5. Product and direction

**The bake-off decision rule is now written down and specific**, which is the important part — "within
five chrF points, no additional critical meaning or entity failures, ≥50% median latency reduction."
Two cautions:

- chrF computed on FLEURS **read** speech will not discriminate conversational quality well; the
  clause carrying the real weight is "no additional critical meaning or entity failures in targeted
  review," which is the human-judged part. The rule is sound but leans on the hardest-to-execute
  component, so the targeted review set should be defined and small before the run, not after.
- The rule decides the **live** path only, and correctly says Ollama stays eligible for offline. Worth
  making sure the run captures enough to decide the offline question too, since re-running is cheap
  only while the harness is fresh.

**The memory-oversubscription run is now opt-in and scoped** — good. The thing worth capturing is not
just latency under pressure but whether degradation is *visible*: does the pipeline report the lag,
or does it just get erratic? Given §1.6, today there is nothing that would report it, so that run
would currently measure a pipeline with no lag instrumentation. Worth adding queue-depth diagnostics
before the experiment, or the experiment cannot answer its own question.

**`PipelineProfile` is a good addition but is not yet reachable.** It sets buffering, context, and
timeout defaults, but no CLI flag selects it and the default is `.live` everywhere (§2.2). The two
operating profiles the README now commits to are real design decisions; they should be selectable
before the first numbers get recorded under whichever one happens to be the default.
